# SSH Brute Force Detection Using Splunk

## Overview

This project demonstrates real-time SSH brute-force detection using Splunk. A Kali Linux system was configured to generate SSH authentication events, while Splunk continuously monitored a live log source for new activity. Failed login attempts were analyzed using SPL queries, and a scheduled alert was configured to identify potential brute-force attacks based on repeated authentication failures from the same source IP address.

## Objective

The objective of this project was to simulate SSH authentication failures, perform real-time log monitoring, and create a detection rule capable of identifying suspicious login behavior commonly associated with brute-force attacks.

## Environment

* Kali Linux
* Splunk Enterprise

## Project Workflow

### 1. Generate Authentication Events

Failed SSH login attempts were generated by repeatedly attempting to authenticate with incorrect credentials.

Example:

```bash
ssh root@localhost
```

### 2. Live Log Collection

SSH authentication events were continuously written to a log file using:

```bash
sudo journalctl -u ssh -f >> /home/kali/ssh_live.log
```

This allowed new SSH events to be captured and appended to the log file in real time.

### 3. Real-Time Monitoring with Splunk

Splunk was configured to monitor:

```text
/home/kali/ssh_live.log
```

As new authentication events were generated, Splunk automatically ingested the data without requiring manual file uploads.

### 4. Detection Query Development

The following SPL query was created to identify source IP addresses generating multiple failed authentication attempts:

```spl
source="/home/kali/ssh_live.log" "Failed password"
| rex "from (?<src_ip>\S+)"
| stats count by src_ip
| where count > 3
```

### Query Logic

* Searches for failed SSH authentication events.
* Extracts the source IP address using regular expressions.
* Counts failed login attempts per IP address.
* Identifies IPs exceeding the defined threshold.
* Flags potentially malicious activity for investigation.

## Alert Configuration

A scheduled alert was created using the detection query.

### Alert Settings

| Setting           | Value                     |
| ----------------- | ------------------------- |
| Alert Name        | SSH Brute Force Detection |
| Alert Type        | Scheduled                 |
| Schedule          | Every 5 Minutes           |
| Trigger Condition | Number of Results > 0     |
| Action            | Add to Triggered Alerts   |

The alert automatically triggers whenever the detection query identifies an IP address exceeding the configured threshold.

## Key Findings

* Multiple failed SSH login attempts were successfully detected.
* Live authentication events were ingested into Splunk in real time.
* Source IP addresses were extracted and analyzed.
* Repeated login failures were identified using threshold-based detection.
* Automated alerting was configured for rapid identification of suspicious activity.

## Security Significance

Repeated authentication failures from the same source IP address may indicate password guessing, credential stuffing, or brute-force attack activity. Monitoring authentication logs in real time enables security teams to quickly identify suspicious behavior and respond before unauthorized access is achieved.
